> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a small always-on-top Electron HUD for Windows 11. It shows every running Claude Code session as a fantasy pixel character, and it lets the user answer permission prompts, multiple-choice questions and opted-in replies without switching windows.

**Architecture:**
- **Main process.** An Electron main process runs a local HTTP server on 127.0.0.1. It receives Claude Code HTTP hooks and holds the blocking ones (PermissionRequest, PreToolUse for AskUserQuestion, and Stop for opted-in sessions) in a queue until the user answers or the hold runs out.
- **Pure modules.** Answer encoding, the queue, the sticky class engine, session parsing and settings merging are each a small pure module with node tests.
- **Renderer.** It draws party frames from a snapshot, using Monet's sprite engine ported from the mockup.

**Tech Stack:** Electron 44.7.2, electron-builder 26.15.3, Node 20 (`node --test`, `node:assert/strict`), plain ES modules (`"type": "module"`). No UI framework.

**Spec:** `C:\Consortis_projects\agent-hud\docs\superpowers\specs\2026-11-16-agent-hud-design.md`. Read it before starting any task. Section numbers below (§) refer to it.

## Global Constraints

- **Platform:** Windows 11 only. Don't use APIs that block a later macOS port.
- **Versions:** Electron 44.7.2, electron-builder 26.15.3, Node 20. Pin both exactly in `package.json`.
- **Network:** the server listens on `127.0.0.1` only. The default port is `47821` (stored in app config).
- **Hook URL and auth:** the hook URL path is always `/agent-hud/hook`. Every request must carry the header `X-Agent-HUD: <secret>`; any request without it gets 403.
- **Hook config:** HTTP hooks with `timeout: 600`, one entry per event, matcher `""`.
- **Hold times:**
  - Permission and choice questions: **60 000 ms from arrival**. Then the HUD releases with an empty 2xx body.
  - Opted-in replies: **540 000 ms**.
- **Blocking cards:** only sessions whose session file has `kind: "interactive"` get them. Every other session gets an immediate empty 200.
- **"No decision" response:** HTTP 200 with an empty body.
- **Focus:** the HUD never steals focus.
  - Show it with `showInactive()`. Keep the window non-focusable until the user clicks into a card.
  - Frameless, transparent, always on top, no taskbar button, a tray icon.
- **Size:** about 272 px wide. Height follows content, capped at 60% of the work area, then it scrolls. Docked bottom-right of the primary display.
- **Sprites:** 24×24 grid drawn at 2×, from Monet's engine. Leave the light direction, outline and silhouettes unchanged.
- **Style (QuestBound house style):**
  - Colours: bg `#18221f`; panels `#2c3a34` / `#3a4a42`; gold `#e0b45c` / `#c9973f` / `#edcb85`; parchment `#f0e9da`; sage `#a9b3a6`; critter `#D97757`.
  - Fonts: IM Fell English (names, display) and Alegreya Sans (UI). Load them from the Google Fonts link used in the mockups, with `serif` / `sans-serif` fallbacks. Don't download font files without asking the user.
- **Not in v1:** no sound, and no starting or stopping sessions.
- **Existing hooks:** never modify Pixel Agents or the user's other hooks in `~/.claude/settings.json`. The HUD's entries are recognised by `/agent-hud/` in their URL.
- **Copy:** the "needs you" seal pulses 3 times on arrival, then glows steadily. A row whose question was handed back reads `Waiting in its window — open ↗`.

## Review Focus

1. **The HUD quits or crashes while holding questions.** Every pending request must be released (empty 200), so no agent waits out its timeout. → Task 6.
2. **The user answers in the native window while the HUD card is open.** The hook connection closes, and the card must disappear instead of lingering or answering into a dead socket. → Task 6.
3. **A command, question or last message containing HTML** (`<img src=x onerror=…>`) must render as text in rows and cards, never as markup. → Task 8.
4. **`settings.json` can't be parsed, has no `hooks` key, or already has HUD entries.**
   - Unparseable: install aborts without writing.
   - Missing key or existing entries: merge works and is idempotent.
   - Either way, other hooks are untouched. → Task 5.
5. **Malformed hook requests** (non-JSON body, unknown `hook_event_name`, missing `tool_input`, body over 1 MB) get 200 empty or 413, and the server never crashes. → Task 6.

### Task 3: Class signals, sticky engine and mood

**Files:**
- Create: `src/main/classes.js`
- Test: `test/classes.test.js`

**Interfaces:**
- Consumes: the normalized event shape `{ sessionId, event, toolName?, toolInput?, at }`, where `event` is the hook's `hook_event_name` and `at` is in ms.
- Produces:
  - `CLASS_IDS`: `['pathfinder','star-reader','runesmith','alchemist','hexbreaker','arbiter','illuminator','loremaster','herald','cartographer','vaultkeeper','summoner']`. These ids match the `CLASSES[].id` values in the roster mockup.
  - `signalsFromEvent(ev) -> Array<{ cls: string, weight: number }>`
  - `createClassEngine({ windowMs = 120000, leadRatio = 1.5, holdMs = 10000 } = {}) -> { push(ev), classOf(sessionId, now): string, activeSubagents(sessionId): number }`
  - `moodOf({ pending: boolean, stoppedAt?: number, lastActivityAt?: number, status?: string }, now) -> 'needs'|'done'|'working'|'idle'`

**The rules this task decides:**
- **Signals** follow the table in spec §5.
  - **Tool names:**
    - `Read`, `Grep`, `Glob` → pathfinder.
    - `Edit`, `Write`, `NotebookEdit` → runesmith, but → loremaster when the `file_path` ends in `.md`, and → cartographer for `.shp .geojson .gpkg .tif .dxf .kml`.
    - `WebSearch`, `WebFetch` → loremaster.
    - `ExitPlanMode` → star-reader.
  - **Bash `command` regexes:**
    - `/\b(test|vitest|jest|pytest|build|lint|tsc)\b/` → alchemist.
    - `/\bgit (push|commit|merge|tag)\b|\bgh\b|\baz (repos|pipelines)\b/` → herald.
    - `/\bpsql\b|\bmigrat/` → vaultkeeper.
    - Any `.sql` path → vaultkeeper.
  - **MCP tools:** names starting `mcp__azure-devops__` → herald.
  - **Agent/Task tool:** use the tool name recorded in SPIKES.md. Map `subagent_type`:
    - `Explore` → pathfinder; `Plan` → star-reader.
    - `change-reviewer`, `review-lead`, `code-reviewer` → arbiter.
    - `artist`, `brush`, `paint` → illuminator.
    - `test-writer` → alchemist; `topcon-deliverables` → cartographer.
    - Anything else gives no signal.
  - **Failures:** `PostToolUseFailure` → hexbreaker.
  - **Weights:** every signal has weight 1; subagent-type signals have weight 3.
- **Sticky switch.** Start every session as `pathfinder`. Each `classOf` call scores the signals inside `windowMs`. A challenger replaces the current class only when both hold:
  - its score ≥ `leadRatio` × the current class's score (or the current class's score is 0);
  - it has been the top scorer continuously for ≥ `holdMs`.
- **Summoner override.** While `activeSubagents(sessionId) >= 2` (count SubagentStart minus SubagentStop), `classOf` returns `summoner`.
- **Mood priority:** `needs` if `pending`; then `done` if `stoppedAt` > `lastActivityAt`; then `working` if `now - lastActivityAt <= 20000` or `status === 'busy'`; else `idle`.

### Task 4: Question queue with hold timers

**Files:**
- Create: `src/main/queue.js`
- Test: `test/queue.test.js`

**Interfaces:**
- Consumes: `RELEASE` from Task 2.
- Produces: `createQueue({ holdMs = 60000, replyMs = 540000, now = Date.now, setTimer = setTimeout, clearTimer = clearTimeout } = {})`, returning:
  - `add(item) -> Promise<object|null>`. `item` is `{ id, sessionId, kind: 'permission'|'choice'|'reply', payload }`. The promise resolves with the response object, or `RELEASE`.
  - `answer(id, response)`: resolves that item and removes it.
  - `drop(id)`: removes it without resolving. Used when the client disconnected.
  - `releaseSession(sessionId, kinds?)`: releases a session's pending items.
  - `releaseAll()`: used on shutdown.
  - `active() -> item|null`: the first in display order.
  - `list() -> item[]`: the display order.
  - `handedBack() -> Array<{ sessionId, at }>`: items released by timeout. Each stays until the next event from that session, which is cleared by `clearHandedBack(sessionId)`.
  - `clearHandedBack(sessionId)`
  - `onChange(fn)`

**The rules this task decides:**
- **Display order:** all `permission` and `choice` items first, in arrival order, then `reply` items in arrival order.
- **Timers:** each item's timer starts at `add` (from arrival). It runs `holdMs` for permission and choice, `replyMs` for reply. On expiry the item resolves `RELEASE` and is recorded in `handedBack`.

### Task 6: Hook server

**Files:**
- Create: `src/main/hook-server.js`
- Test: `test/hook-server.test.js`

**Interfaces:**
- Consumes:
  - `createQueue` (Task 4) and `RELEASE` (Task 2).
  - `isInteractive(sessionId) -> boolean`, `replyOptIn(sessionId) -> boolean` (injected).
- Produces: `createHookServer({ port, secret, queue, isInteractive, replyOptIn, onEvent }) -> { listen(): Promise<number>, close(): Promise<void> }`
  - `listen()` resolves to the bound port; `port: 0` is allowed in tests.
  - `onEvent(normalizedEvent)` is called for every valid request before routing.
  - `normalizedEvent` is `{ sessionId: body.session_id, event: body.hook_event_name, toolName: body.tool_name, toolInput: body.tool_input, cwd: body.cwd, at: Date.now(), raw: body }`.

**Routing (spec §6.1):**
- `PermissionRequest` from an interactive session → `queue.add({ kind: 'permission' })`.
- `PreToolUse` with `tool_name === 'AskUserQuestion'` from an interactive session → `queue.add({ kind: 'choice' })`.
- `Stop` from an interactive session with `replyOptIn` → `queue.add({ kind: 'reply' })`.
- Everything else → 200 with an empty body at once.
- Every queued item's `payload` is the raw hook body.
- A `UserPromptSubmit` for a session calls `queue.releaseSession(sessionId, ['reply'])`. This is spike 3's mitigation.
- A `PostToolUse` or `PostToolUseFailure` for a session releases that session's pending `permission` items with the same `tool_name`. The tool can only have run if the user answered natively.
- When the queue resolves `RELEASE` → 200 empty. An object → 200 with JSON body.

**Edge rules (Review Focus 1, 2, 5):**
- Wrong or missing `X-Agent-HUD` → 403.
- Non-POST or a path other than `/agent-hud/hook` → 404.
- Body over 1 MB → 413.
- Invalid JSON or no `hook_event_name` → 200 empty, and `onEvent` is not called.
- Client disconnect before the answer → `queue.drop(id)`.
- `close()` calls `queue.releaseAll()` and flushes those responses before closing the server.

    - `snapshot()` returns `{ agents: AgentView[], card: CardView|null, next: string|null, counts: { total, needs } }`.
    - `AgentView` is `{ id, display, cls, mood, activity, familiars, replyOptIn, entrypoint, cwd, handedBack }`.
    - `CardView` is `{ id, kind, display, cls, payload }`.

**The rules this task decides:**
- **Display name:** `basename(cwd) + ' · ' + short`. The short part is:
  - for `nameSource === 'derived'`, the text after the last `-` (`arsenal-e0` → `e0`);
  - otherwise, the full `name`.
- **Activity lines:**

  | Event | Line |
  |---|---|
  | `Read` | `reading <basename>` |
  | `Edit` / `Write` | `editing <basename>` |
  | `Bash` | `running <command, first 40 chars>` |
  | `Grep` / `Glob` | `searching code` |
  | `WebSearch` | `searching the web` |
  | `WebFetch` | `reading <hostname>` |
  | Agent/Task | `sending a <subagent_type> helper` |
  | `UserPromptSubmit` | `thinking` |
  | anything else | `tool_name` |

- **`store.onEvent(ev)`:**
  - calls `engine.push(ev)`;
  - sets `lastActivityAt` on `UserPromptSubmit`, `PreToolUse` and `PostToolUse*`;
  - sets `stoppedAt` on `Stop`;
  - remembers the last `Notification` type;
  - calls `queue.clearHandedBack(ev.sessionId)` for any event that isn't a `Notification`.
- **Mood input.** `moodOf` receives `pending` = any queued item for the session, or a handed-back item, or a last Notification of type `permission_prompt`, `elicitation_dialog` or `agent_needs_input` with no activity since.
- **Familiars:** `min(engine.activeSubagents(id), 3)`.
- **Next line:** `next` reads `Next: <display> asks a question` (or `… wants a reply`) for the second item in `queue.list()`.
